# AGENTS.md — apps/website

This is the website workspace of the Capann monorepo (`@capann/website`). The
repository-wide rules, layout, and the shared packages are in the root
`AGENTS.md`; this file covers the website.

## What this is
Marketing landing page for **Capann**, a browser extension (draw, point, screenshot, and record the tab on any page, free; Premium at $7/month adds share links with playback, marks that scroll with the page, and screenshot styling). Built by Duowork.
React site with the landing page (`/`), an interactive `/playground` that renders three realistic sample pages so visitors can annotate them with the installed extension, `/privacy`, and three Capann Premium utility pages (`/verify`, `/view-my-links`, `/upgraded`; see below). The landing page follows the design approach agreed with the owner (below) and the **ai-slop-design** skill (`.agents/skills/ai-slop-design/SKILL.md`): use it for any change to a page's layout, styling, or copy. The landing copy follows the shipped extension: what is free and what is Premium, and the price, must match `apps/extension` (`PREMIUM_PRICE_LABEL` in `src/shared/features.ts`, and the feature table in the root `AGENTS.md`). The design export's "Pro, $10 one-time" pricing is outdated.

## Stack
Vite 8 + React 19 (JS, no TypeScript) + Tailwind CSS v4 (`@tailwindcss/vite`) + `react-router` 7. Node 22. Lint: `oxlint`. The Premium helpers in `src/premium/*.js` carry JSDoc types from `@capann/contract` and are checked by `npm run typecheck` (`tsconfig.json`); the rest of the site isn't type-checked. React must stay on the same version as the extension (see the root `AGENTS.md`).

## Commands
Install once at the repository root (`npm install`). From the root:
- `npm run website:dev` — local dev server
- `npm run website:build` — production build to `apps/website/dist/` (always verify changes with this). `postbuild` copies `dist/index.html` to `dist/404.html` so deep links like `/playground` work on static hosting.
- `npm run website:preview` — serve `dist/` locally
- `npm run website:lint` — oxlint
- `npm run typecheck` — every workspace, including this site's Premium helpers
- `npm run website:capture` — retake the product shots in `src/assets/product/` (see "Product imagery")

The same scripts without the `website:` prefix work from inside `apps/website`. There is no deploy script: GitHub Actions deploys the site (below).

## Deployment
Deployed at `https://capann.duowork.tech` from the monorepo's own GitHub Pages by `.github/workflows/website.yml`. Every push to `main` that touches `apps/website/`, `packages/`, the root `package.json`, or the lockfile runs `npm ci`, lint, the website typecheck, and the build, then publishes `dist/`; it can also be run by hand from the Actions tab (the `github-pages` environment only accepts `main` unless its branch rules are widened).
- One-time repository settings (listed at the top of the workflow): Pages source "GitHub Actions", custom domain `capann.duowork.tech` with HTTPS enforced, and the Actions **variables** `VITE_CAPANN_API_URL`, `VITE_CAPANN_EXTENSION_IDS`, `VITE_CAPANN_INSTALL_URL`. CI has no `.env.production` (it is gitignored), so those variables are what the deployed site gets; the workflow warns when `VITE_CAPANN_EXTENSION_IDS` is empty, since Premium sign-in can't finish without it.
- The custom domain is a Pages setting, so no `CNAME` file is needed in `public/`. DNS (at WhoGoHost): `capann.duowork.tech` must be a CNAME to the repository owner's Pages host, `<owner>.github.io` (`duowork.github.io` for `Duowork/Capann`).
- `vite.config.js` sets `base: '/'` for the custom domain. If the site ever moves to a project path (`duowork.github.io/Capann/`), `base` must change with it.
- `postbuild` writes `dist/404.html` as an SPA fallback so deep links like `/playground` and `/privacy` boot the router on static hosting.
- `index.html` asset URLs are rewritten by Vite automatically; **hardcoded absolute public paths in JSX break under a non-root base** — always prefix with `import.meta.env.BASE_URL` (see the logo `<img>` usage in `src/pages/LandingPage.jsx` and `src/pages/PlaygroundPage.jsx`).

## Styling rules
- Tailwind utilities for general styling; custom CSS only where necessary (`src/index.css`, `src/playground/playground.css`).
- Playground sample pages live in `src/playground/samples/` and are styled by `playground.css`, entirely scoped under `.pg-sample` with `fb-` / `te-` / `dg-` prefixes. Keep it that way so sample palettes and selectors never leak into the site or the extension overlay. Around them, the playground uses the same page, header, and footer as the rest of the site.
- **Tokens and components come from `@capann/design`** (`packages/design/capann.css`), which `src/index.css` imports. Its `@theme` only maps Tailwind's utility names to the design file's variables (`--color-fg: var(--text-primary)`, …) and holds no values of its own; change a colour or size in the design file. Utility names: `canvas`, `fg`, `body`, `muted`, `line`, `accent` (violet text), `rec-text` (mint text), `error`, `track`, `panel`, `elevated`, `inverse` / `on-inverse`, and the fixed `ink`, `paper` (light text on ink), `brand-paper`, `browser`, `draw` / `draw-hover`, `rec`, `save-ink`. Fonts (`font-sans`) and motion (`ease-morph`, `duration-morph`) read the design file's variables of the same name.
- **Components:** use the design file's classes for buttons (`cp-button` + `cp-button--primary` / `--secondary` / `--save`), links (`cp-link`), icon buttons (`cp-icon-button`), glass (`cp-glass`), headings (`cp-display` for the hero, `cp-title` for a page's h1, `cp-heading` for a section), `cp-lead`, notices (`cp-notice` + `--success` / `--error`), `cp-status-dot`, hairline lists (`cp-list`), plans (`cp-plan`, `cp-plan--featured`), keycaps (`cp-keycap`), and dialogs (`cp-dialog`). They live in the `components` layer, so Tailwind utilities override them for size and spacing (`cp-button px-4 text-[13.5px]`).
- Custom helpers: `.duration-morph`, `.ease-morph`, `.delay-stagger-row`, `.font-display`. Landing-only: `.feature-card` / `.feature-card__shade` / `.feature-stack-end` (the stacked deck), `.premium-halo` / `.premium-halo__ring` (the deck's Premium card), `.float-card` (tilted illustrations, `--tilt`), `.scroll-demo` (the scrolling-marks vignette). Motion stops under `prefers-reduced-motion`.
- **Light and dark.** Dark is the default; the nav's sun/moon button (`src/components/ThemeToggle.jsx`) switches to a warm-paper light theme and remembers it in `localStorage` (`capann-theme`), and other open tabs follow. An inline script in `index.html` applies a saved light theme before the first paint (no dark flash); keep its key and colours in step with `ThemeToggle`. Light mode sets `data-theme="light"` on `<html>`, and the design file redefines its colour variables under `:root[data-theme="light"]` (Tailwind v4 utilities read `var(--color-…)`, which point at them, so no class changes per theme). Use the `light:` variant only when a value can't be a token.
  - **Themed tokens** for page-level UI: `bg-canvas` (page), `text-fg`, `border-line` / `ring-line`, `text-accent` (violet text and outlines), `text-rec-text` (mint text), `text-error` (errors, time running out), `bg-fg/[…]` for soft fills, the surfaces and text (`bg-panel`, `bg-elevated`, `text-muted`, `text-body`, …), `shadow-[var(--shadow-float)]`, and `bg-inverse` / `text-on-inverse` (the "Why go Premium?" panel: paper on the dark site, ink on the light one).
  - **Fixed brand colours** never change with the theme: `ink`, `paper`, `brand-paper`, `draw` (the violet buttons keep `bg-draw text-ink` in both), `rec`, `hl`, and the browser mock. Use them only for things that are always dark or always light, like the Premium illustrations and the product shots.
  - **Logos:** put both icons in and mark them `on-dark` (the light-ink icon) and `on-light` (the dark-ink icon); the design file shows the one that fits.
- **Anchor targets must not be `overflow-hidden`.** That makes the element a scroll container, and Chrome then ignores its `scroll-mt-*` on `#fragment` links, so the target lands under the fixed header. Use `overflow-clip` (clips the same, no scroll container) on anything a link points to, and give it `scroll-mt-28` (the floating nav).
- Never introduce new colours, radii, or fonts silently: add them to the design file and flag them in its header.
- Tailwind v4 tree-shakes unused non-color theme vars from output; utilities still generate on demand. Verified pattern: use the class, `npm run build`, grep `dist/assets/*.css`.

## Design approach (agreed, every page)
Product-led and editorial, like linear.app. It applies to every page: the landing page, the playground, the privacy page, and the Premium pages; check every change against the ai-slop-design skill (`.agents/skills/ai-slop-design`).
- **Structure:** one 1280px column (`CONTAINER`) with generous space between sections and an occasional hairline. The "Why go Premium?" panel is the only full-width break.
- **Header:** the shared floating, rounded nav (`SiteHeader`): transparent at the top, a frosted pill once the page scrolls. The Premium pages use its `minimal` version (logo, Back to site, theme toggle).
- **Headings:** no labels above them, one colour each. Big Shoulders Display (uppercase) only for the landing hero headline and the wordmark; every other heading is Sora, sentence case.
- **Icons:** Phosphor in the `fill` weight. For line glyphs whose fill version sits in a square (Check, Plus), use the circle variant (`CheckCircle`, `PlusCircle`).
- **Product imagery:** real screenshots of the extension on the playground's sample pages (see "Product imagery" below). The "Why go Premium?" illustrations are the one agreed exception: drawn in HTML and tilted, with a real styled screenshot among them.
- **Containers:** the pricing plans are the one set of cards. Feature deck cards are flat panels. No gradients or glows, except the agreed mint halo travelling round the deck's Premium card.
- **Colour:** violet is for the primary action and active states. Secondary actions are a soft fill, and links are underlined text without arrows.
- **Buttons:** only the header, the hero, and the plans have them. Everything else uses text links.
- **Motion:** only where it explains something (the stacked deck, the halo, the scrolling-marks vignette, tab cross-fades). Nothing bobs, pulses, or counts up.
- **Copy:** short, no em dashes, no sentence under every heading. Owner-supplied text (the privacy policy) is never reworded.

## App structure
- `src/App.jsx` — router shell (`BrowserRouter` with the Vite base as `basename`, `/` landing, `/playground`, `/privacy`, `/verify`, `/view-my-links`, `/upgraded`, catch-all landing) + scroll-to-top on route change.
- `src/components/SiteHeader.jsx` — the shared floating nav (landing, playground, privacy) with its mobile menu; `minimal` drops the section links, the button, and the menu for the Premium pages. Section links are in-page anchors on the landing page and routes back to `/#section` elsewhere; `LandingPage` scrolls to a section it was opened at.
- `src/components/ThemeToggle.jsx` — the light/dark switch in `SiteHeader` and `PremiumLayout` (see "Light and dark" above).
- `src/components/SiteFooter.jsx` — shared footer: the wordmark, link columns (Product, Help, Duowork) on a hairline, then the copyright and "Built by Duowork".
- `src/pages/LandingPage.jsx` — the landing page. Data arrays at the top (`USE_CASES`, `FEATURE_GROUPS`, `FREE_FEATURES`, `PREMIUM_FEATURES`, `SHORTCUTS`, `PANEL_SHORTCUTS`, `FAQS`) and the prices (`MONTHLY_PRICE`, `DAY_PRICE`, `MAX_DAYS`). Pricing copy also appears in `index.html` (meta descriptions, JSON-LD offers) and `public/llms.txt`; change all three together.
  - **Order:** hero (display headline, one sentence, "Get Capann free" + playground link, the real hero shot) · one-paragraph statement · `UseCases` · features (`FeatureStack`) · `PremiumPanel` · `PricingSection` · `ShortcutsSection` · `FaqSection` · footer.
  - **`UseCases`** ("For anyone who explains things on a screen"): one tab per audience (Founders, Product teams, Consultants, Educators and trainers, Customer support, Agencies), each with a fill icon, a real shot of Capann on a matching playground sample, and one line on how they use it. The tab row scrolls sideways on small screens; arrow keys, Home, and End move between tabs.
  - **`FeatureStack`** ("What you get"): a stacked deck of flat cards, each numbered, with a fill icon after its title, a short list, and a real shot. Sticky cards slide over each other, shrinking and dimming the covered ones (`--cover`); `--deck-height` makes every card as tall as the tallest. The last (Premium) card carries the mint halo. A plain list on phones and windows under 720px tall, and no shrinking or travelling light under `prefers-reduced-motion`.
  - **`PremiumPanel`** ("Why go Premium?"): a full-screen panel in the inverse colours (paper on the dark site, ink on the light one) with a plain headline in the middle and four tilted illustrations around it from 1280px up (a grid below that): the player, "Link copied", a real styled screenshot, and a page whose circled mark scrolls with it. No testimonials or ratings: Capann has none.
  - **`PricingSection`**: Free, `PayPerDayCard`, Premium (the one card on `bg-elevated`, with the one violet plan button), 2 + 1 under 1280px, stacked on phones. `PayPerDayCard`: a 1–30 day slider at `DAY_PRICE` a day; at 30 days it offers the subscription instead. Pay-per-day is website only, and every pricing button is a placeholder until checkout exists.
  - **`ShortcutsSection`**: keycaps (`KeyCombo`, labelled ⌥ Option / ⌘ Cmd on a Mac, Alt / Ctrl elsewhere) in hairline-separated columns, with what each global shortcut does while recording, then a row of panel shortcuts. **`FaqSection`**: a native `<details>` accordion on hairlines, heading on the left.
- **Product imagery:** `src/assets/product/*.webp`, every one the real Premium extension on the playground's sample pages, made by `scripts/capture-product.mjs` (`npm run website:capture`, or `-- --only=hero,use-support`). It needs the premium extension build and the website build, and Playwright's Chromium once (`npx playwright install chromium`). Retake shots when the extension's UI or the samples change; the shots' `width`/`height` attributes in `LandingPage.jsx` must match the files (1600×885 for sample shots).
- `src/pages/PlaygroundPage.jsx` — `/playground`, one page: a heading, one line on starting Capann (toolbar icon or Alt+Shift+S), sample tabs (Feedback, Teaching, Bug report) with Reset and Maximize, the sample itself, and "Things to try". Maximize animates the sample into a full-window overlay (FLIP) and Esc returns, with focus back on Maximize. A one-time notice on phones says the extension needs a desktop. No extension detection, no annotation canvas: the installed extension does the drawing.
- `src/pages/PrivacyPage.jsx` — `/privacy`: heading, the owner's introduction, the dates, then the policy with a sticky contents list (desktop) that highlights the section being read. Section titles live in `SECTIONS`; the body is rendered with small local `Paragraph`/`SubHeading`/`Bullets`/`Section` helpers. Policy copy is owner-supplied — don't rewrite it, only re-port it.
- `src/playground/experiences.js` — the samples' tab labels, blurbs, and screen-reader challenges, plus "Things to try".
- `src/playground/samples/{FeedbackSample,TeachSample,DiagnoseSample}.jsx` — three self-contained sample pages with local-only state (all reset by remounting via a reset key).
- `src/playground/playground.css` — scoped sample styles and palettes.
- `src/main.jsx` — entry; `src/index.css` — imports Tailwind and `@capann/design`, maps the theme, site base styles, and the landing-only CSS; `index.html` — fonts (Big Shoulders Display + Sora via Google Fonts), favicons, meta.
- Brand icon in use: `svg/capann-icon-light.svg` ("light" = for dark backgrounds, per assets README).

## Capann Premium pages
Sign-in and link recovery for the Premium extension. Everything these pages exchange with the API and the extension is defined in `@capann/contract` (`packages/contract`): change it there, never by hand here, and the API, extension, and this site's helpers are all type-checked against it. No accounts or passwords: a user is an email proven by magic links.
- `src/pages/VerifyPage.jsx` — `/verify?token=…` (single-use, 15-min login token). Pings each extension ID (`capann-ping`) on load; exchanges the token (`POST /api/auth/verify`) **only on click**, because email scanners open links. Hands the 30-day session token to the extension (`capann-session`), and keeps it in memory so a failed hand-off can be retried without spending the link again. Never stores tokens.
- `src/pages/ViewMyLinksPage.jsx` — `/view-my-links?token=…` (reusable 15-min links token). `GET /api/links/list` with `Authorization: Bearer`; the links are a plain list on hairlines (Play, Copy link, Open); countdowns run on server time (skew from the response's `now`), re-rendered every 30s and on tab focus; under 24h turns red (`text-error`): the link is about to go. **Play** (session playback, Premium) opens the recording in a modal on this page, `src/premium/RecordingPlayer.jsx`: a native `<dialog>` with an HTML5 `<video>` streaming the link itself (the API serves byte ranges). There is no watch page. MediaRecorder's WebM has no duration, so the player seeks far past the end once to make the browser find it, then rewinds and plays (the extension's Links tab does the same).
- `src/pages/UpgradedPage.jsx` — `/upgraded`, the Bachs post-checkout redirect. Sends `capann-refresh`, retrying briefly because the webhook can lag.
- API calls go through `@capann/api-client` (`exchangeLoginToken`, `listLinks`, `ApiError`; the server's `error.message` is user-safe) with `API_URL` from `config.js`. Routes for `/verify` and `/view-my-links` come from the contract's `WEBSITE_PATHS`, which the API uses to build the emailed links.
- `src/premium/` — `config.js` (env), `extension.js` (`findExtension`, `handOffSession`, `refreshExtension`, and the underlying `sendToExtension`; pages never build messages themselves, so every message and reply is checked here), `chrome.d.ts` (the `chrome.runtime` slice a page gets), `usePrivatePage.js` (`noindex` + `referrer: no-referrer` while mounted, restored on leave), `PremiumLayout.jsx` (the minimal `SiteHeader`, a 720px column straight on the page with no card (880px for the links list), the site footer, `PageHeading` (Sora, sentence case, one colour), `Lead`, `DoneMark`, `Notice` (a soft fill per tone, no border), the live `StatusLine`, and the button classes: violet primary, soft-fill secondary). Errors use `role="alert"`, progress `role="status"`; the red is the design file's `--text-error`.
- Origin is strict: the extension accepts messages only from its exact site origin (`https://capann.duowork.tech`, or `http://localhost:5173` in a local build). Never serve these pages from `www` or another host. `vite.config.js` pins the dev server to port 5173 (`strictPort`) for the same reason.
- Env (Vite, all public): `VITE_CAPANN_API_URL`, `VITE_CAPANN_EXTENSION_IDS` (comma-separated; Web Store ID first, then any unpacked IDs), `VITE_CAPANN_INSTALL_URL` (falls back to `/#pricing`). They live in local, gitignored `.env.development` / `.env.production` (dev: `VITE_CAPANN_API_URL=http://127.0.0.1:8799` plus your unpacked ID; prod: the production API, the Web Store ID and listing URL). Without them the API defaults to production and no extension is found, so `/verify` always asks the visitor to install Capann.
- Local end-to-end, from the repository root: `npm run api:dev -- --port 8799` (magic links print to `apps/api/.wrangler-dev.log` with `EMAIL_TRANSPORT=console`), `npm run build:backend` (the extension, pointed at the local API and this site), load `apps/extension/dist` unpacked, put its ID in `.env.development.local` (or `VITE_CAPANN_EXTENSION_IDS=<id> npm run website:dev`), then `npm run website:dev`.
